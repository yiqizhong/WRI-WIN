# Windows Auto-Update R2 Release Runbook

## Overview

This runbook documents the manual process for building and publishing Writer updates to Cloudflare R2 to enable Windows auto-updates via `electron-updater`.

## Build

Build the Windows desktop application:

```bash
npm run build --workspace @writer/desktop
```

This outputs the following artifacts to `apps/desktop/dist-electron/`:
- `Writer-Setup-<version>.exe` — the NSIS installer executable
- `Writer-Setup-<version>.exe.blockmap` — block map for differential updates
- `latest.yml` — update metadata (auto-generated by electron-builder)

## Upload to R2

Upload the built artifacts to the R2 bucket root (`https://pub-d230cd20641545cf88369006a73de152.r2.dev`) in the **exact following order**:

### Step 1: Upload the Installer

Upload `Writer-Setup-<version>.exe` to the bucket root.

```
Writer-Setup-<version>.exe → https://pub-d230cd20641545cf88369006a73de152.r2.dev/Writer-Setup-<version>.exe
```

### Step 2: Upload the Block Map

Upload `Writer-Setup-<version>.exe.blockmap` to the bucket root.

```
Writer-Setup-<version>.exe.blockmap → https://pub-d230cd20641545cf88369006a73de152.r2.dev/Writer-Setup-<version>.exe.blockmap
```

### Step 3: Upload Update Metadata (LAST)

Upload `latest.yml` to the bucket root **last**. This is the "publish" step—once `latest.yml` is live, electron-updater clients will detect the new version and begin downloading the installer.

```
latest.yml → https://pub-d230cd20641545cf88369006a73de152.r2.dev/latest.yml
```

## Notes

- **Order matters:** Upload the installer and block map before `latest.yml`. If you upload `latest.yml` first, clients may download the installer before it's ready.
- **Versioning:** The version string in filenames comes from `apps/desktop/package.json` (`"version": "0.1.0"`). Increment this before building.
- **Differential updates:** The `.blockmap` file enables delta downloads via `electron-updater`, reducing bandwidth for end-users on subsequent updates.
- **Update detection:** Once `latest.yml` is live on R2, clients running Writer will check for updates on next launch or after a configured interval.

## Example

Given version `0.2.0`:

1. Build: `npm run build --workspace @writer/desktop`
2. Upload `Writer-Setup-0.2.0.exe`
3. Upload `Writer-Setup-0.2.0.exe.blockmap`
4. Upload `latest.yml` (contains version 0.2.0 and download URL)
5. Clients detect the new version and download the installer
