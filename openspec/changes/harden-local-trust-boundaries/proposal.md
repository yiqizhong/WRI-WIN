# Harden local trust boundaries

## Why

A full-codebase security audit of `main` (2026-06-09, see `docs/code-quality-audit-2026-06-09.md`)
found that the local daemon **trusts its local network completely**: it binds to `127.0.0.1`
but enforces no auth token, no `Host` allowlist, and no `Origin` rejection, and parses request
bodies regardless of `Content-Type`. This single weakness (V1) makes several otherwise-local
issues remotely triggerable from a malicious web page (via CSRF for state changes, and DNS
rebinding for full read access) or another local process:

- **V2 (HIGH)** — `resolveAdapterForRun` has no `isKnownAdapterId` gate, so `POST /agents/runs`
  with `adapterId:"echo"` reaches `spawn(cmd.exe, ["/c","echo", prompt])` with no metacharacter
  escaping → command injection / RCE on Windows.
- **V3 (HIGH)** — `POST /paste-text/attachments` reads an arbitrary request-supplied `filePath`
  and returns its full contents (schema is `z.string().min(1)`, no confinement).
- **V4 (MED)** — the screenshot route builds a path from an unsanitized `sessionId`
  (`decodeURIComponent` after the `[^/]+` match → `%2f` traversal); constrained to `*.png`.
- **V5 (MED)** — `shell.openExternal` is called with an unvalidated, remote-influenced MCP OAuth
  `authorizationUrl` (no scheme allowlist) → `file://`/UNC/custom schemes reach the OS shell.
- **V6 (LOW)** — `writer:save-text-file`/`exportPdf` IPC write to a renderer-supplied absolute
  path with no confinement (defense-in-depth; needs a renderer foothold).

## What Changes

- **local-daemon**: add a per-launch bearer token (generated by the daemon, shared with the
  Electron app via a `~/.writer`-scoped token file so daemon reuse still works), validated on
  every route except `/health`; add a `Host` allowlist and active `Origin` rejection. Confine
  paste-text `filePath` and screenshot `sessionId`/path to allowed roots (`assertInsideDir`).
- **agent-adapter-runtime**: gate `resolveAdapterForRun` on `isKnownAdapterId` (dev/echo adapters
  not runnable from request input); harden `buildEchoSpawn` to escape `cmd.exe` metacharacters
  (reuse `escapeCmdMetacharacters`) or avoid `cmd /c`.
- **desktop-shell**: allowlist URL schemes (`https`/`http`/`mailto`) in `writer:open-external`
  and `setWindowOpenHandler`; stop trusting renderer-supplied absolute paths in the save/export
  IPC handlers (combine pick+write, or track dialog-approved paths).

Spec deltas under `specs/<capability>/spec.md` are authored per finding at implementation time.

## Impact

- **Affected specs:** `local-daemon`, `agent-adapter-runtime`, `desktop-shell`.
- **Affected code:** `apps/daemon/src/{router,server,http,config,paste-text,figma-screenshots,agents}.ts`,
  `apps/daemon/src/routes/{platform,review}.ts`, `packages/agent-adapters/src/{echo-adapter}.ts`,
  `apps/desktop/electron/{main,preload,ensure-daemon}.cjs`, `apps/desktop/src/daemon-client.ts`.
- **User-visible:** none in normal use. The V1 auth-token remediation has UX risk if done
  carelessly (app blank on launch if a reused daemon's token mismatches; `<img src>` screenshots
  can't carry an auth header) — both mitigated by the token-file approach + exempting/`?token=`
  for screenshot GETs. Risk is in our code, not the user's network/environment.
- **No behavior change** to legitimate renderer→daemon traffic once the token is threaded through.
